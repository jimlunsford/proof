## Failures, corrections, and limits

No unresolved assertion failures or skipped checks remain in the executed suites. The expected historical negative control detected the known canonical failure at `ba684c6cd37d30c2292a88916f48c3ca519f19fe`; this is required evidence that the HTTP test detects the old bug.

The first expanded browser-fixture attempt called Proof helpers in the same PHP request that switched themes. WordPress does not load the new theme's functions on `switch_theme()`, so the fixture now explicitly requires the active theme's functions before testing its defaults and Customizer. This changes only disposable test setup.

Environment preparation also encountered a missing native PHP binary, a shared Playground download-cache collision during concurrent first boots, unavailable Playwright browser downloads, and a native browser launch failure in the restricted workspace. PHP was extracted into the disposable workspace; the validated WordPress archive was reused with serial initialization; browser acceptance completed on Apollo. These failures were not hidden or converted into passing assertions.

The pre-existing test-only dependency tree reports two npm audit findings: high severity `body-parser` and moderate severity `qs`. The manifest and lockfile remain unchanged; no production theme dependency is added. Dependency maintenance is a separate follow-up. SQLite/Playground and Chromium testing do not establish MariaDB, production cache/PHP-FPM behavior, Safari/Firefox, or a complete screen-reader/WCAG audit.
